# sing-box 整机分流菜单

入口脚本与部署资源均由 GitHub 仓库提供。资源包文件名包含内容摘要，安装时校验完整 SHA256。

在 Debian 服务器上以 root 运行：

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/coexacx/singbox-manager/main/singbox.sh)
```

菜单 1 安装 sing-box 和 HTTPS、Shadowsocks、WireGuard、SOCKS5 四种模板。已有安装再次选择 1 会更新管理器并补齐新增模板，保留节点资料和当前代理。菜单 2–4 分别编辑 HTTPS、Shadowsocks、WireGuard；菜单 14 编辑 SOCKS5。密码和私钥输入时不回显。

菜单 5–7、15 分别启用 HTTPS、Shadowsocks、WireGuard、SOCKS5。启用前检查必填项和 sing-box 配置，再通过本地 SOCKS 监听验证 HTTPS 连通性；启用后等待 TUN 接口或透明规则及检测入口就绪，再复检并显示代理出口 IP。单个服务限流、超时或响应无效时会自动切换。等待超时或检测失败时恢复先前服务和配置。WireGuard 的 MTU 范围为 576–9000，未设置时默认 1280。启用时会让当前 SSH 客户端地址和 SSH 服务端口绕开 TUN，以保护管理连接。

SOCKS5 的服务器地址和端口为必填项；用户名、密码需同时填写或同时留空。在菜单 14 的认证项输入 `-` 可清空该项，直接回车保留原值。默认仅代理 TCP，匹配代理规则的 UDP 流量会被拒绝，以便支持回退的应用改用 TCP；只有上游支持 SOCKS5 UDP ASSOCIATE 时才开启 `udp_enabled`。启用检测验证 TCP 连接，不能代表上游支持 UDP。SOCKS5 模板沿用 HTTPS 模板的全部目标站点规则。

## 多节点与自动连接（菜单 17）

将节点集中放入 `/etc/sing-box/manager/nodes.txt`，每个节点前使用独立数字行 `1`、`2`、`3` 分隔；安装时会放入不含真实凭据的格式示例。也可以在导入提示中指定其他文件路径。支持标准 WireGuard `[Interface]` / `[Peer]` 配置、`https://`、`socks5://`、`ss://` 链接、`用户名:密码@地址:端口`（SOCKS5），以及单节点 sing-box JSON / 本管理器节点 JSON。Shadowsocks 支持 SIP002 和旧式完整 Base64 链接，暂不支持插件。

WireGuard 缺少 DNS 时使用 `1.1.1.1`，缺少 MTU 时使用 `1280`；已填写值保留。保留多个 IPv4/IPv6 地址、AllowedIPs、可选预共享密钥和保活时间。每个编号只放一个 Peer；文件中的注释不会作为配置执行。

导入后转换并校验配置，只测服务器延迟；实际连接成功后才查询出口和中文地理位置。重复配置跳过。节点库位于 `/etc/sing-box/manager/node-store.json`，权限 0600，不可上传仓库。

子菜单：1 导入，2 查看，3 编辑，4 选定连接，5 自动选择 TCPing/Ping 最低延迟，6 关闭自动连接，7 全部服务器测速，8 删除，9 改名，10 设置备用复测间隔，0 返回。

## 测速、自动连接与清理（管理接口 6）

- 导入和批量测速只测服务器：HTTPS、Shadowsocks、SOCKS5 使用 TCP 握手，WireGuard 使用 ICMP ping，不发送代理认证、TLS 或出口 IP 请求。
- 自动连接按 TCPing/Ping 延迟升序尝试；端口可达不代表代理账号有效，选中的节点还必须通过真实 HTTPS 连通性验证。实际失败立即删除并尝试下一节点；成功后保持连接，不因其他节点变快而切换。
- 备用节点分散轮询，每次最多检测一个到期节点，轮询之间至少 60 秒；同一节点默认至少间隔 1800 秒，节点多时依序排队。子菜单 10 调整复测间隔。手动全库测速与导入依次执行，节点间至少 2 秒，5 分钟内复用测速结果。
- 备用节点 TCP 握手明确失败立即清除，不再等待三轮。WireGuard 没有 ICMP 回复只代表延迟未知，保留节点并排在已测得延迟的候选之后。当前连接由真实代理检测确认故障，避免仅凭一次新 TCP 握手失败中断仍可用的连接。
- 自动模式每分钟调度当前连接检查，成功结果缓存 120 秒。每次先请求一个 HTTPS 204 地址，失败才使用第二地址复核；两个地址均连接失败即删除并切换，不累计失败轮数。服务进程停止时尝试恢复，不单凭进程状态删除节点。
- 连接成功后查询代理出口 IP，并按可获得的中文地理位置命名。IP 服务依次尝试 ipinfo.io、ipwho.is、api.ipify.org，总预算 15 秒；地理查询失败不会把可用代理删除。旧节点名称保留，旧 HTTP 耗时不再参与排序。
- 频率限制仅针对本服务器：真实连接尝试间隔至少 15 秒，真实检测每小时预算 180 个请求额度（连接预留 8，健康检测 2，IP 查询 3）；TCPing/Ping 每小时最多 600 次节点测量。配置在 `/etc/sing-box/manager/probe-policy.json`。这些是本机默认策略，并非供应商承诺的安全频率。
- 本机检测额度用完、上游明确 429 限流、检测网站返回非预期响应、TUN/服务未就绪或本机直连路由错误时延后检测，不作为失效删除。上游 429 暂停本机真实检测一小时；节点认证失败则删除该节点，继续尝试后续候选。
- 运行中节点的新配置实际失败时丢弃待应用修改，保留原有可用配置。手动停用代理会关闭自动连接；备用服务器巡检仍继续。

## Telegram 通知

菜单 12 配置 Bot Token 与个人数字 chat_id。使用 HTTPS Bot API `sendMessage`，绑定物理网卡发送；每 30 分钟报告内核、本机 IP、当前节点、出口 IP、地理位置及 TCPing/Ping 测速结果。

连接、故障切换、立即删除、编辑、模式切换、停止、全部不可用/恢复和检测延后均有专项通知。事件发送前提交节点状态，最多等待 25 秒，失败入队重试。事件使用已有出口信息；定时通知复用 30 分钟内的 IP 查询缓存，查询暂不可用时标明旧采样时间，不将 IP 查询失败单独判定为代理故障。

菜单 8 停用代理。菜单 9 清除本管理器安装的配置、节点资料及其安装的 sing-box 软件包；若安装前已有 sing-box，恢复原配置和服务状态。菜单 10 重新检测当前代理并显示出口 IP。菜单 11 开关 TUN，菜单 12 配置 Telegram Bot 监测，菜单 13 退出。菜单 16 切换分流 / 全局模式。菜单顶部显示 sing-box 版本、TUN 状态、运行协议、流量模式、Telegram 状态和最近检测到的出口 IP。

默认采用分流模式：模板目标站点走代理，其余直连。全局模式将普通 TCP / UDP 流量交给所选代理，并保留 SSH、代理自身建连和 Telegram 告警等必要直连；上游仅支持 TCP 时，UDP 仍会被拒绝。四种协议均支持 TUN 和 TProxy 下的模式切换，切换失败时回滚；停用代理时修改模式会在下次启用时生效。Telegram 通知也会显示当前分流 / 全局模式。

Telegram 配置位于 `/etc/sing-box/manager/telegram.json`，仅 root 和 sing-box 服务用户可读。`node-summary.json` 仅含名称、状态、延迟、出口信息等允许字段，不包含节点密码或密钥。菜单 8 先发送停止事件，再关闭通知定时器；菜单 9 清理管理器与节点库。

默认开启 TUN。关闭 TUN 后使用 nftables TProxy 透明接管本机 TCP、UDP 和 DNS 流量，仍按所选协议模板分流；SSH 服务端口直连。切换时会复检当前节点，失败则恢复先前配置。安装器会安装 nftables 并创建 sing-box 的 systemd 启停钩子，使透明规则随服务启动和停止。卸载时清除这些规则和钩子。

节点资料仅 root 可读，位置为 `/etc/sing-box/manager/https.json`、`shadowsocks.json`、`wg.json`、`socks5.json`。当前启用的完整配置为 `/etc/sing-box/config.json`。查看状态和日志：

运行中的 sing-box 会在 `127.0.0.1:18081` 提供仅本机可访问的 SOCKS 检测入口；菜单在切换后和手动检测时通过此入口依次查询三个独立的 IP 服务。


默认直连 DNS 为 `1.1.1.1`，可在对应节点资料中修改。WireGuard 未填写隧道 DNS 时默认使用 `1.1.1.1`。分流规则来自原始三个模板，目标站点走选定节点，其他流量直连。程序自带加密 DNS 或隐藏域名时，匹配取决于 IP 规则与协议嗅探。

## 更新兼容性

主菜单的编辑和启用入口与节点库共用状态。运行中节点的编辑暂存为待应用；自动巡检与故障切换使用已生效的配置。其他同协议节点的编辑不会覆盖当前配置。

切换前检测、服务启动、启用后复检分别限制为 60 / 60 / 75 秒。切换失败会恢复配置、运行模式、出口检测信息及服务状态。安装通过可撤销的 systemd 覆盖配置加载 `/usr/bin/sing-box` 与 `/etc/sing-box/config.json`；原服务文件保留，卸载时移除覆盖并恢复原配置。
